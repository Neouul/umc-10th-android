## 3. ⚠️ Critical Issues

- **스레드 동시성 관리가 결여된 상태 업데이트 (UI State Loss 위험)**:
  - [BaseViewModel.kt](file:///E:/Documents/Coding/Android/UMC/umc-10th-android/week10/mission/app/src/main/java/com/neouul/umc10android/week10/core/base/BaseViewModel.kt)의 `updateState` 메서드는 현재 `_uiState.value = update(_uiState.value)` 형태로 이전 값을 읽어 직접 값을 덮어씁니다. 여러 비동기 작업이 백그라운드 스레드에서 동시에 `updateState`를 요청할 경우 Race Condition에 의한 일부 상태 유실(State Loss)이 발생할 수 있습니다.
- **컴파일 경고 및 유연하지 않은 이미지 대체 로직**:
  - [DetailScreen.kt](file:///E:/Documents/Coding/Android/UMC/umc-10th-android/week10/mission/app/src/main/java/com/neouul/umc10android/week10/presentation/screen/detail/DetailScreen.kt)의 68라인 `product.img.ifEmpty { R.drawable.img_detail }` 코드는 `String` 객체의 확장 함수에서 `Int` 타입인 리소스 ID를 전달하고 있어 반환 타입이 공통 상위 인터페이스인 `Any`로 암시적 캐스팅됩니다. 이는 타입 안전성을 해치고 추후 런타임 버그의 원인이 될 수 있습니다.
- **비효율적인 Flow 수집 및 중복 상태 관리**:
  - [ShopViewModel.kt](file:///E:/Documents/Coding/Android/UMC/umc-10th-android/week10/mission/app/src/main/java/com/neouul/umc10android/week10/presentation/screen/shop/ShopViewModel.kt)에서는 내부 로컬 상태인 `_selectedTabIndex`와 `uiState` 내부의 `selectedTabIndex`가 중복적으로 정의되어 관리에 혼선을 줍니다. 또한 `combine`으로 결합된 데이터를 `init` 블록에서 `collect`하여 수동으로 매번 `updateState`를 실행하는 명령형 상태 제어 방식을 취하고 있어 리소스를 비효율적으로 사용합니다.
- **화면 구조 계층의 UX 기획 오류 (Bottom Bar 노출 이슈)**:
  - [NavigationRoot.kt](file:///E:/Documents/Coding/Android/UMC/umc-10th-android/week10/mission/app/src/main/java/com/neouul/umc10android/week10/core/routing/NavigationRoot.kt)를 보면 상품 상세 페이지인 `Route.ProductDetail`이 메인 화면 전용 내비게이션 컨트롤러인 `mainNavController` 하위의 `Route.MainGraph`에 중첩되어 있습니다. 이로 인해 상세 페이지 진입 시에도 하단 탭바(BottomNavigationBar)가 화면 하단에 불필요하게 유지되는 모바일 UX 결함이 존재합니다.

## 4. 💡 Refactoring Suggestions

- **`updateState` 스레드 안전성 보장**:
  - Kotlin Coroutines Flow 라이브러리가 공식 지원하는 `MutableStateFlow.update { ... }` 확장 함수를 사용하여 원자적 상태 갱신을 하도록 수정합니다.
- **선언적 Flow 조합 스타일로 아키텍처 재구조화**:
  - `ShopViewModel` 내 중복된 탭 변수를 제거하고, Repository의 데이터 스트림과 탭 제어 스트림을 단일 읽기 전용 `StateFlow`로 바인딩하여 `stateIn`으로 결합하는 구조로 개선합니다.
- **Coil 3 이미지 라이브러리 타입 매치 최적화**:
  - 이미지 URL 스트림이 비어 있을 때는 `null` 또는 문자열 형태로 전달하고, Coil의 `error()` 파라미터에 대체 이미지 페인터를 명시하는 방식으로 수정합니다.
- **내비게이션 계층 정상화**:
  - 전체 화면을 차지해야 하는 `Route.ProductDetail`을 메인 그래프 밖의 전역 `navController`가 처리하도록 호출 경로를 수정하여 상세 화면에서 하단 바가 보이지 않도록 변경합니다.

* `kotlinx.coroutines.flow.update`를 활용하여 원자적으로 업데이트를 수행합니다.

```kotlin
// Before
abstract class BaseViewModel<STATE : UiState>(
    initialPageState: STATE,
) : ViewModel() {
    protected val _uiState = MutableStateFlow(initialPageState)
    val uiState: StateFlow<STATE>
        get() = _uiState.asStateFlow()

    protected fun updateState(update: (STATE) -> STATE) {
        _uiState.value = update(_uiState.value) // 스레드 경합 시 동시 업데이트 누락 위험
    }
}

// After
import kotlinx.coroutines.flow.update

abstract class BaseViewModel<STATE : UiState>(
    initialPageState: STATE,
) : ViewModel() {
    protected val _uiState = MutableStateFlow(initialPageState)
    val uiState: StateFlow<STATE> = _uiState.asStateFlow() // get() 보단 직접 인스턴스 참조 전달

    protected fun updateState(update: (STATE) -> STATE) {
        _uiState.update { update(it) } // 원자적으로 갱신되어 스레드 안전함
    }
}
```

### 3) [ShopViewModel.kt](file:///E:/Documents/Coding/Android/UMC/umc-10th-android/week10/mission/app/src/main/java/com/neouul/umc10android/week10/presentation/screen/shop/ShopViewModel.kt) 선언적 Flow 상태 조합 리팩토링
* `init` 내부의 수동 `collect` 방식을 걷어내고 결합된 `stateIn` 흐름으로 재구축합니다.

```kotlin
// Before
@HiltViewModel
class ShopViewModel @Inject constructor(
    private val productRepository: ProductRepository
) : BaseViewModel<ShopState>(ShopState()) {

    private val _selectedTabIndex = MutableStateFlow(0)

    init {
        viewModelScope.launch {
            productRepository.getAllProducts()
                .combine(_selectedTabIndex) { products, index ->
                    products to index
                }.collect { (products, index) ->
                    val filtered = when (index) {
                        1 -> products.filter { it.category.contains("Tops", ignoreCase = true) }
                        2 -> products.filter { it.isBestSeller }
                        else -> products
                    }
                    updateState {
                        it.copy(
                            products = filtered,
                            selectedTabIndex = index
                        )
                    }
                }
        }
    }

    fun onTabSelected(index: Int) {
        _selectedTabIndex.value = index
    }
}

// After
import kotlinx.coroutines.flow.SharingStarted
import kotlinx.coroutines.flow.stateIn

@HiltViewModel
class ShopViewModel @Inject constructor(
    private val productRepository: ProductRepository
) : BaseViewModel<ShopState>(ShopState()) {

    private val _selectedTabIndex = MutableStateFlow(0)

    // UI에서 관찰할 단일 읽기 전용 상태 조합 파이프라인
    val combinedState = combine(
        productRepository.getAllProducts(),
        _selectedTabIndex
    ) { products, index ->
        val filtered = when (index) {
            1 -> products.filter { it.category.contains("Tops", ignoreCase = true) }
            2 -> products.filter { it.isBestSeller }
            else -> products
        }
        ShopState(
            products = filtered,
            selectedTabIndex = index
        )
    }.stateIn(
        scope = viewModelScope,
        started = SharingStarted.WhileSubscribed(5000),
        initialValue = ShopState()
    )

    fun onTabSelected(index: Int) {
        _selectedTabIndex.value = index
    }
}
```

## 6. 📌 Key Considerations

- **선언적 Flow 조합 전환 시 초기 상태 유의**:
  - `stateIn` 기반 선언적 흐름으로 뷰모델 코드를 리팩토링할 경우, 화면 진입 직후 첫 프레임(초기 상태값 방출) 시점에 탭 리스트(`tabs = listOf(...)`) 구성 및 로딩 UI가 정상적으로 표시되는지 면밀히 확인해야 합니다.
- **이미지 로딩 컴포넌트 크기 고정**:
  - [ProductItem.kt](file:///E:/Documents/Coding/Android/UMC/umc-10th-android/week10/mission/app/src/main/java/com/neouul/umc10android/week10/presentation/component/ProductItem.kt)의 `AsyncImage` 요소는 `modifier = Modifier`가 빈 값으로 들어가 있습니다. 가끔 레이아웃의 종속성 변화에 따라 가로세로 크기가 불안정하게 잡힐 우려가 있으므로, 부모 Box 내에서 올바른 비율을 차지하도록 `modifier = Modifier.fillMaxSize()` 처리를 하는 것을 강력히 권장합니다.
